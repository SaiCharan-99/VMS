# API

The full, interactive reference is generated by FastAPI:

- **Swagger UI:** `http://<host>/docs`
- **ReDoc:** `http://<host>/redoc`
- **OpenAPI JSON:** `http://<host>/openapi.json` (a copy is committed as `frontend/openapi.json`;
  the frontend's TypeScript types are generated from it and CI fails if they drift)

Every route lives under `/api/v1`. Errors are `{"detail": ...}`. List endpoints take `page` and
`page_size` and return `{items, total, page, page_size}`.

## Authentication

Two ways, sent on every request:

| Who | Header | How to get it |
|---|---|---|
| People (web UI, scripts acting as a user) | `Authorization: Bearer <jwt>` | `POST /api/v1/auth/login` |
| Integrations (warehouse systems, scanners) | `X-API-Key: vms_…` | Admin → API keys in the UI (shown once) |

An API key acts like an **operator**: it can upload and can see only the videos it uploaded.

### Log in

```bash
curl -s -X POST http://localhost/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@vms.local","password":"admin-demo-1"}'
# {"access_token":"eyJ…","token_type":"bearer","expires_in":43200,"user":{…}}
```

Tokens expire after `VMS_JWT_TTL_HOURS` (12 h). Too many failed logins return 429.

## Upload and get a verdict (API key)

```bash
KEY=vms_xxxxxxxx

# 1. Upload: 201 {video, job}. A byte-identical file returns 200 with duplicate=true.
curl -s -H "X-API-Key: $KEY" \
  -F "file=@parcel-123.mp4" -F "process_type=Return" -F "awb=AWB123456" \
  http://localhost/api/v1/videos

# 2. Poll the job until status is "done" or "failed" (progress goes 0..1).
curl -s -H "X-API-Key: $KEY" http://localhost/api/v1/jobs/42

# 3. Read the result: final_status pass|review|fail, score, steps, checks, evidence URLs.
curl -s -H "X-API-Key: $KEY" http://localhost/api/v1/videos/17
```

`process_type` is `Forward` (packing) or `Return` (unboxing). The analysis result format is
versioned (`schema_version` "2.0", IMPLEMENTATION.md §5).

The `stream_url` and evidence `url` fields in responses are signed and expire, so `<video>` and
`<img>` tags can load them without a header. Fetch a fresh detail response to get new ones.

## Main endpoints

| Method + path | Who |
|---|---|
| `GET /health` | anyone |
| `POST /auth/login`, `GET /auth/me`, `POST /auth/change-password` | users |
| `POST /videos`, `GET /videos`, `GET /videos/{id}`, `GET /videos/{id}/stream` | any user or API key (operators and keys: own videos only) |
| `GET /jobs/{id}`, `GET /evidence/{id}`, `GET /rubrics`, `GET /stations` | any user or API key |
| `POST /videos/{id}/reanalyze`, `POST /videos/{id}/reviews`, `PUT /videos/{id}/dispute` | reviewer, admin |
| `GET /review-queue`, `GET /reports/summary`, `GET /reports/export.csv` | reviewer, admin |
| `DELETE /videos/{id}`, `/admin/*` | admin |

The legacy `POST /analyze` and `GET /results` endpoints were removed in v1.0. Use the flow above.
